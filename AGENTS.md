# AGENTS.md

Рабочие заметки для людей и агентов, которые ведут этот репозиторий.

## Что это

kurator — офлайновый разбор фотографий: находит точные дубликаты, визуально
похожие кадры, burst-серии и тематические группы. Всё считается на машине
пользователя, сеть не используется.

Ключевые свойства, которые нельзя нарушать:

- **Ничего не удаляется.** Файлы переезжают в `.kurator/quarantine/` с
  манифестом, откат — `kurator undo`. Это основа доверия к инструменту.
- **Burst-кадры не трогаются никогда.** Даже побайтно одинаковые с
  оригиналом. Это альтернативные кадры одного момента.
- **Сети в рантайме нет.** Единственное обращение наружу — `pull-model.sh`,
  и там сверяется sha256.
- **Индекс инкрементальный.** Повторный проход пропускает файлы с неизменным
  размером и mtime.

## Стек

Рантайм-зависимости выбираются по одному правилу: **format coverage
прежде всего**. kurator читает фотографии, и снимок, который он не может
открыть, для пользователя просто потерян — никаких эмбеддингов, никаких
pHash, никаких находок, молча и среди прочих. Одна лишняя библиотека в
поставке этому не противопоставим.

Cписок зависимостей ограничен смыслом. Чего добавлять нельзя — такого, 
что можно сделать стандартной библиотекой, и такого, что тянет за собой 
веб-сервер, ORM, CLI-фреймворк или собственный формат данных. 
Веб-интерфейс по-прежнему три статических файла и 
`ThreadingHTTPServer`, и это правило проверяется тестом.

| Пакет | Версия | Зачем |
|-------|--------|-------|
| `numpy` | ≥1.26, в lock 2.5 | эмбеддинги, хеши, кластеризация |
| `pillow` | ≥10.3, в lock 12.3 | декодирование, EXIF, превью, контакт-листы |
| `pillow-heif` | ≥1.0, в lock 1.8 | HEIF/HEIC/AVIF — снимки с айфона и Android |
| `onnxruntime` | ≥1.18, в lock 1.31 | прогон модели на CPU |
| `pytest` | ≥8.2, в lock 9.1 | тесты, только для разработки |
| `pyinstaller` | ≥6.10, только в `dev` | сборка `.app` и `.dmg`, не попадает в поставку |

Из стандартной библиотеки используется многое: `sqlite3` для индекса,
`http.server` для веб-интерфейса, `hashlib` для md5, `threading` для
фоновой индексации, `urllib` для скачивания весов.

Новая зависимость в рантайме — только вместе с проверкой, что формат
действительно читается **собранным** приложением. `libheif` уезжает в
бандл силами PyInstaller, и проверить это на macOS можно, а на Windows —
только в CI. Поэтому `packaging/verify_bundle.py` создаёт настоящие
`.heic` и `.avif` и требует, чтобы эмбеддингов было столько же,
сколько файлов.

Инструменты: **uv** для окружения и зависимостей, **hatchling** как
сборщик, Python **3.11+**. Модель весов не хранится в git.

Модель: визуальная башня **SigLIP2 base patch16-224, int8**, репозиторий
`onnx-community/siglip2-base-patch16-224-ONNX`, Apache-2.0, 90 МБ, файл
`vision_model_int8.onnx`, вход NCHW float32 224×224, выход `pooler_output`
768 измерений, нормализация L2.

## Структура

```
src/kurator/
  config.py      пути, пороги, расширения — правится при смене модели
  hashing.py     md5, pHash (DCT 32×32), dHash, хамминг на numpy
  imaging.py     EXIF, препроцессинг 224×224
  encoder.py     сессия onnxruntime, батчинг
  indexer.py     обход папки, инкрементальность
  db.py          SQLite-индекс, потокобезопасный доступ
  dedupe.py      exact / near / burst, analyze() — единая точка входа
  cluster.py     leader-кластеризация по центроидам
  quarantine.py  перенос, манифест, откат
  contact.py     контакт-листы
  report.py      markdown и html
  evaluate.py    точность против эталонной разметки
  web/           локальный HTTP-сервер и одностраничный UI
scripts/
  pull-model.sh      скачивание весов с проверкой sha256
  make_testset.py    синтетический архив + ground_truth.json
```

## Команды

```bash
uv sync                        # окружение
./scripts/pull-model.sh        # веса, 90 МБ, единственный выход в сеть
uv run pytest -q               # тесты; без весов часть пропускается
uv run kurator --help

# рабочий цикл на тестовом архиве
uv run python scripts/make_testset.py /tmp/kurator-test 180
uv run kurator index /tmp/kurator-test
uv run kurator evaluate /tmp/kurator-test --sweep
```

Те же команды гоняет CI на каждом пуше: быстрый `pytest` без весов на трёх
системах и сквозной прогон с моделью на Linux, см. `.github/workflows/ci.yml`.
Локально повторить его целиком можно ровно этими строками — на macOS они дают
тот же результат, что и джоб.

## Ветки и итерации

Ветка называется просто номером, без префиксов и описаний: `001`, `002`,
`003` и так далее. Номер сквозной и не переиспользуется.

**Каждая итерация разработки — отдельная ветка с номером.** Ветка
создаётся от `main` и живёт, пока этап не закончен. Правки идут в неё
коммитами, а не в `main` напрямую: иначе через месяц не разобрать, где
что ломалось.

```bash
git switch -c 001      # новая итерация, от свежего main
git switch -c 002      # следующая, когда 001 закончена
```

**Мержить в `main` — только по явной команде.**

Агент не мержит сам: готовность к релизу —
это оценка, а решение о релизе принимает человек.

Договорились об одном исключении. Агент закончил **цельный этап, достойный
релиза** — и **спрашивает**, можно ли мержить, перечислив: что вошло в
этап, какие метрики получились, какие ограничения остались. Вопрос задаётся
в том виде, на который можно ответить «да» или «нет», без подготовки.

Основная ветка называется `main`, если пользователь говорит о `master`, то имеет в виду `main`. Пуш в `origin` — тоже только по явной команде: отправка наружу это не то же самое, что локальная работа, и решение одно на то и другое.

## Правила работы

**Единая точка входа для подсчёта кандидатов — `dedupe.analyze()`.**
`dups`, `report`, `apply`, веб-интерфейс и `evaluate` обязаны считать
одинаково. Расхождение между ними уже стоило одного неверного отчёта о
безопасности: `evaluate` показывал 37 утечек burst-кадров, которых на самом
деле не было.

**Правка порогов и правил сопровождается цифрами.** `kurator evaluate` до и
после, результат — в описании коммита. Эталон зафиксирован: точные
дубликаты 1.000, похожие кадры 0.306 по точности при полноте 1.000, ловушки
0.767, карантин по умолчанию 1.000, burst 1.000. Любая правка, которая
портит хоть одну из этих пяти, обязана объяснить почему.

Три из пяти держатся на 1.000 не потому, что находки идеальны, а потому
что пороги настроены именно на это: похожие кадры лишь предлагаются к
просмотру и в карантин по умолчанию не попадают. Низкая точность похожих —
это дефолт, а не авария.

**Пути в индексе хранятся с разделителем `/` независимо от ОС.** На Windows
`str(relative_to())` даёт обратные слэши, и отчёт с веб-интерфейсом
разъезжаются. См. ROADMAP, раздел P0.1.

**Новые зависимости — по смыслу, а не по счёту.** Зависимость оправдана,
если без неё kurator не может прочитать чужой снимок, посчитать хеш или
отдать результат. Не оправдана, если задача решается стандартной
библиотекой или если библиотека тянет за собой веб-сервер, ORM или
формат данных. Перед добавлением проверяется, что колесо существует под
все три платформы — иначе поддержка формата будет заявлена на словах.

**Формат в списке — значит читается.** Расширение, которое kurator
обещает, обязано открываться настоящим файлом. Это проверяется в
`tests/test_formats.py` двумя способами: Pillow должен знать декодер, и
формат должен переживать реальный круг «записать и прочитать обратно».
Список расширений и список детекторов в коде расходятся не могут.

**Собранное приложение обязано работать само.** Две ошибки уже стоили
времени, и обе выглядели как «приложение собралось, значит всё в
порядке»:

- веб-интерфейс — это три файла, которые сервер читает с диска.
  PyInstaller про импорты их не видит, и без явного `datas` в spec
  приложение запускается и отдаёт 404 на всё подряд;
- адрес модели при `sys.frozen` ведёт внутрь бандла, а не в корень
  проекта. Собранному приложению весы нужны свои, и они кладутся
  в бандл явно.

Сборка проверяется не только тем, что `.app` создался: он должен
открыться, отдать главную страницу и **посчитать эмбеддинги** —
это единственный способ убедиться, что `onnxruntime` уехал в бандл
целиком.

## ROADMAP.md обязателен

**[ROADMAP.md](ROADMAP.md) — единственный источник правды о том, что не сделано.**
Устаревший роадмап хуже, чем его отсутствие: через месяц он будет вводить в
заблуждение и тебя, и любого агента, который откроет репозиторий.

### Перед каждым коммитом

1. **Сверься с роадмапом.** Открыл `ROADMAP.md` — найди, к какому пункту
   относится изменение. Если такого пункта нет, а изменение заметное, добавь
   его.
2. **Закрывая пункт** — перенеси его в «Сделано» с датой и одной строкой о том,
   как проверял. Не удаляй: по истории видно, что уже чинили и почему.
3. **Меняя приоритеты** — поправь порядок внутри блока и объясни в коммите,
   почему. Приоритет меняется, когда выясняется что-то новое, и это само по
   себе повод записать.
4. **Находя баг** — не чини молча. Запиши в P0 с описанием, что ломается и
   чем это проверяется, даже если починил в этом же коммите. Баг, который
   проявился, но не описан, повторится.

### Когда роадмап пополняется

| Ситуация | Что делать |
|----------|------------|
| Придумал новую идею | Записать с описанием пользы и сложности |
| Нашёл баг | Записать с описанием симптома и способа проверки |
| Идея отвергнута | P3, с причиной. Чтобы не поднимали заново |
| Не хватило времени на пункт | Переставить порядок в блоке, не молча пропустить |
| Пункт оказался неактуальным | Пометить и объяснить в коммите, а не выкидывать |

### Чего в роадмапе не должно быть

Он не превращается в отчёт о проделанной работе. Формат — «что сделать и как
понять, что сделано». Если пункт оброс деталями реализации, детали пора в
коммит или в код.

### Android

В [Omen4Dead/kurator-android](https://github.com/Omen4Dead/kurator-android) —
отдельный репозиторий со своим роадмапом. Общее только правило 1.1
(золотые тесты на хеши): когда появится Android-порт, он обязан упаковывать
биты pHash в том же порядке, что и ПК-версия, иначе индексы перестанут
совпадать, и это обнаружится не сразу. Правки сюда из того репозитория
не тащат.
