# kurator

Находит в папке с фотографиями точные дубликаты, похожие кадры, серии из одного момента и группы снимков про одно и то же. Всё считается на вашем компьютере, сеть не используется.

## Что он делает

- **Точные дубликаты** — по md5 байтов. Конфликтные копии `Имя (1).jpg`, дубли после переноса между устройствами.
- **Похожие кадры (near-дубли)** — тот же кадр в другом качестве, после
  ресайза или мелкой правки. Сначала отсекаются по расстоянию pHash, а найденное
  делится косинусом эмбеддинга на вероятный дубль и просто похожую композицию.
- **Серии из одного момента (burst)** — `Имя (0).jpg`, `Имя (1).jpg` и кадры,
  снятые подряд за пару секунд и похожие друг на друга.
- **Группы по сюжету (кластеры)** — визуальные группы по эмбеддингам, без
  запроса: «всё это про одно и то же». Снимок попадает в группу, только если
  похож на её центроид.
- **Отчёт** — markdown, html и контакт-листы с превью, где оставляемый кадр
  обведён и подписан «оставляю».

**Форматы.** 
- JPEG, PNG, WebP, TIFF, BMP, DIB, GIF, HEIC/HEIF, AVIF, JPEG 2000, PCX, TGA, JFIF 
- и _сырые_ фото с камер: CR2, NEF,
ARW, ORF, RW2, DNG, PEF, SRW, ERF.

Всего 35 расширений, и список не расходится с тем, что действительно
читается: у каждого обещанного формата есть проверка, что он открывается
настоящим файлом, а собранное приложение обязано посчитать эмбеддинг по
всем.

Не читаются RAF (Fujifilm) и X3F (Sigma) — это не TIFF-контейнеры, и Pillow
их не открывает. Их нет в списке намеренно: поддержка, которая выглядит
включённой и молча пропускает файлы, хуже её отсутствия.

## Чего он не делает

**Не удаляет фотографии сам.** Перенос — это перенос: файлы уезжают в
`.kurator/quarantine/` внутри папки с фотографиями,
откат возвращает всё на место. Никакого удаления без явной команды.

**Не решает за вас.** По умолчанию в карантин уходят только побайтно одинаковые
файлы. Похожие кадры показываются для просмотра; включить их в перенос можно
явно точечным решением по группе в интерфейсе.

**Не отправляет в облако.** Сетевого кода в рантайме нет: единственное обращение
наружу — `./scripts/pull-model.sh`, при сборке из исходников.

**Интерфейс виден только вашему компьютеру.** Он слушает `localhost` и требует
случайный токен, который создаётся при запуске, поэтому чужая страница в
браузере не обратится к вашим фотографиям.

**Данные о снимках лежат рядом с ними.** В папке появляется скрытая `.kurator/`
с индексом: имена файлов, размеры, даты съёмки, хеши и векторные признаки на
снимок, около 3 КБ. Удалите её — получите чистый архив.

## Установка

### Приложением

**macOS** — Apple Silicon:

1. Скачайте [kurator.dmg](https://github.com/Omen4Dead/kurator/releases/latest).
2. Откройте образ и перетащите `kurator.app` в «Программы».
3. Запустите — браузер откроется сам.

При первом запуске macOS спросит, откуда взялось приложение: это проверка
подписи, которой у бесплатной сборки нет. Нажмите «Открыть» ещё раз, и
вопрос больше не появится. Полностью бесшовная установка требует
Apple Developer ID и нотаризации.

**Windows:**

1. Скачайте [kurator-setup.exe](https://github.com/Omen4Dead/kurator/releases/latest)
   из того же релиза.
2. Запустите — установщик предложит папку, по умолчанию `Программы\kurator`,
   и спросит, создавать ли значок на рабочем столе.
3. Запустите kurator — браузер откроется сам.

Установщик кладёт ярлык в меню «Пуск», там же — «Удалить kurator».
Значок на рабочем столе по умолчанию не создаётся, его надо отметить в
мастере.

Права администратора запрашиваются: ставить по умолчанию в «Программы»
иначе нельзя. Само приложению права не нужны — оно пишет только в свою
папку и в `~/.kurator`.

Модель внутри обоих установщиков, интернет не нужен.

### Из исходников

Нужен Python 3.11 и [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/Omen4Dead/kurator.git
cd kurator

curl -LsSf https://astral.sh/uv/install.sh | sh
uv sync
./scripts/pull-model.sh   # веса, 90 МБ — единственный выход в сеть

uv run kurator models      # проверить, что модель на месте
```

### Собрать установщик

```bash
./packaging/build.sh       # macOS: dist/kurator.app и dist/kurator.dmg
```

На Windows то же самое, и для этого есть PowerShell-скрипт:

```powershell
powershell -ExecutionPolicy Bypass -File .\packaging\build-windows.ps1
```

PyInstaller не умеет кросс-компиляцию, поэтому Windows-сборку можно сделать
только на Windows. Обычно это и не требуется: установщик `kurator-setup.exe`
собирается в CI при мёрже в `main` и лежит в
[релизах](https://github.com/Omen4Dead/kurator/releases/latest).

Есть установщики под macOS (Apple Silicon) и под Windows, оба собираются
в CI и проверяются запуском: приложение должно открыть страницу, посчитать
эмбеддинги и прочитать снимки в форматах, которые kurator обещает. Под Linux
установщика нет, там kurator работает из исходников.

#### Длинные пути в Windows

Лимит в 260 символов — системный, и реальные архивы в него упираются:

```
Photos from 2024\Отпуск\Испания\Барселона\IMG_20240704_101112.jpg
```

Включается один раз через PowerShell от администратора:

```powershell
New-ItemProperty -Path 'HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem' `
  -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force
```

После этого нужен вход в систему заново. Ошибки станут заметны сразу:
`OSError: [Errno 206] Filename or extension is too long`. Если снимок
не читается, kurator не пропускает его молча — он попадает в счётчик
`нечитаемых файлов` при индексации.

## Использование

```bash
# индекс: обойти папку, посчитать хеши и эмбеддинги
uv run kurator index ~/Pictures

# что нашли
uv run kurator stats ~/Pictures
uv run kurator dups ~/Pictures
uv run kurator clusters ~/Pictures

# подобрать пороги под свой архив
uv run kurator calibrate ~/Pictures

# замерить точность против эталонной разметки
uv run kurator evaluate /tmp/kurator-test

# отчёт с превью
uv run kurator report ~/Pictures
open ~/Pictures/out/report.html

# интерфейс в браузере (локально, 127.0.0.1)
uv run kurator ui ~/Pictures

# перенос кандидатов — сначала посмотреть, потом сделать
uv run kurator apply ~/Pictures --dry-run
uv run kurator apply ~/Pictures --yes
uv run kurator undo ~/Pictures --yes
```

Повторный `index` инкрементальный: файлы с неизменным размером и mtime
пропускаются. Пересчитать всё — `index --rehash`.

### Пороги и как их проверить

<details>
<summary>Замеры на синтетическом наборе и подбор порогов под свой архив</summary>

Порогов два:
- `pHash` — насколько сильно кадры должны совпадать по геометрии,
- `cosine` — насколько близко должно быть то, что изображено.

У похожих кадров pHash обязателен, косинус лишь делит находку на «вероятный дубль» и «просто похожую композицию», поэтому подбор порогов — это в первую очередь выбор pHash.

Набор для проверки — не «должно работать», а мера. Генератор кладёт рядом с
архивом `ground_truth.json`: какой файл от чего произошёл, включая **ловушки** —
снимки с той же композицией, но другим сюжетом. Без ловушек ложные срабатывания
вообще нечем измерить.

На 265 размеченных снимках при дефолтных порогах (`pHash ≤ 4`, `cosine ≥ 0.9`):

```
метрика                                                TP   FP   FN    prec  recall      F1
точные дубликаты (md5)                                  8    0    0   1.000   1.000   1.000
похожие кадры (pHash ≤ 4, cosine ≥ 0.9)                11    6    0   0.647   1.000   0.786
ловушки не названы дублями                             26    4    4   0.867   0.867   0.867
карантин по умолчанию (только exact) чист               8    0    0   1.000   1.000   1.000
если разрешить near-дубли вручную                      11    6    0   0.647   1.000   0.786
burst: ни один кадр не уходит в карантин               36    0    0   1.000   1.000   1.000
```

Читать это надо так:

- **Карантин по умолчанию чист.** `apply` трогает только `exact` —
  побайтно одинаковые файлы. Сомнений тут нет, и именно это даёт 1.000.
- **У похожих кадров точность 0.647, и это ожидаемо.** Примерно каждая
  третья предложенная похожая пара — не дубль: даже на пороге 4 набор
  ловит перекрашенные варианты одной композиции. Поэтому похожие кадры
  только предлагаются к просмотру. Включать их в перенос стоит руками,
  и это осознанный размен полноты на безопасность.
- **Полнота у похожих кадров равна 1.000** — настоящие дубли не теряются.

Порог `cosine` на этой фикстуре не срабатывает ни при каком значении от 0.80
до 0.98 — результаты совпадают побитово. Плоские геометрические фигуры тестовых
сцен модель считает более похожими друг на друга, чем на перекрашенный вариант
той же композиции. На живых фотографиях проверили отдельно: у подтверждённого
дубликата косинус 0.9659, у ложного срабатывания на скриншотах 0.9605 — то
есть развести их можно, но это подгонка под две точки, а не измерение. Практически
подбирать пороги нужно в диапазоне pHash, вся работа там.

Проверить на своём архиве:

```bash
# таблица порогов: TP/FP/FN, точность, полнота, F1, утечки burst
uv run kurator evaluate ~/Pictures --sweep
```

**Эталонной разметки на настоящих фотографиях не существует.** Там `evaluate`
покажет, что kurator считает дублями, а сверить с истиной можно только глазами
по контакт-листам.

Флаги `--phash` и `--cosine` есть у `dups`, `evaluate`, `report`, `apply` и в
веб-интерфейсе.

</details>

## Как это устроено внутри

<details>
<summary>Модель, индекс и откуда берётся результат</summary>

| Слой | Что | Размер |
|------|-----|--------|
| Эмбеддинги | [SigLIP2 base, int8](https://huggingface.co/onnx-community/siglip2-base-patch16-224-ONNX) | 90 МБ |
| Рантайм | onnxruntime, CPU | — |
| Перцептивные хеши | pHash (DCT 32×32) + dHash, своя реализация на numpy | — |

Каждый снимок проходит через визуальную нейросеть SigLIP2 — она превращает
картинку в 768 чисел. Два снимка похожи тем больше, чем ближе эти числа.
Точные копии дополнительно сравниваются по контрольной сумме байтов.

Индекс лежит в `<корень>/.kurator/index.db` и переезжает вместе со снимками:
скопировали архив на диск — скопировался и разбор. Эмбеддинги хранятся как
`float32`-блобы, ~3 КБ на снимок.

Серии из одного момента определяются по времени съёмки **и** похожести
вместе. Только по времени они находятся у любой съёмки, а только по похожести —
у любого повторяющегося сюжета.

Пороги в индексации не участвуют, поэтому их смена не требует переиндексации.

</details>

## Для разработчика

```bash
uv run pytest -q
```

Тесты, которым нужна модель, пропускаются, если веса не скачаны. Сквозной тест
генерирует архив, индексирует его и требует, чтобы ни одно расхождение с
эталоном не осталось.

Те же тесты гоняет CI: быстрый `pytest` без весов на macOS, Linux и Windows и
сквозной прогон с моделью на Linux. Пока сборка проверялась только руками на
macOS, поломки на других системах не всплывали — например, вызов макосовской
`sips`, который вне её молча возвращает пустоту.

Генератор тестового набора кладёт в архив точные дубли, похожие кадры разного
качества, burst-серии, битые jpeg, файлы без EXIF и не-картинки:

```bash
uv run python scripts/make_testset.py /tmp/kurator-test 180
```

Устройство проекта — какие файлы за что отвечают — описано в
[AGENTS.md](AGENTS.md), в разделе «Структура». Здесь оно намеренно не
дублируется.

Правила ведения проекта и требования к зависимостям — тоже в
[AGENTS.md](AGENTS.md).

## Про логотип

Курица в деловом костюме — каламбур на само название: **kurator** от
лат. *curator* («смотритель, хранитель коллекции») и рус. «курица».
Программа действительно работает как смотритель: обходит хозяйство,
наводит порядок и ничего не разоряет.
